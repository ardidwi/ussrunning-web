# INT-01 Auth frontend cutover

Production FE-02 now delegates signup/login/provider recovery to the installed Managed Neon Auth SDK, with BE-02 own account provisioning and BE-03 proof/own-session resend. No auth dependency, provider config, secrets or role hierarchy change. The server operation boundary rejects unsupported/duplicate fields; no caller account ID/role or verification flag is accepted. Signup validates legal consent, provisions via trusted session, records explicit privacy acknowledgment/audit separately without marketing opt-in, and enters pending verification. Missing session requires sign-in; provisioning/delivery failures remain honest, never active signup success.

BE-03 consumes proof authoritatively. The UI does not activate accounts. It then refreshes trusted own-account state and displays active/pending/suspended/deactivated/unknown; profile gates remain. Anonymous or unavailable state refresh is explicitly unknown. Resend is input-free and requires own trusted session; only backend retry timing drives countdown. Expired, consumed, invalid and provider delivery failures map safe codes without tokens/raw exceptions.

Email GET remains non-mutating and nonce/CSP protected. Its fragment is transferred to `/login?flow=verify` and cleared immediately; explicit UI confirmation calls the same BE-03 service. Verification query tokens are not serialized into React props or accepted as proof. Password reset uses the provider's genuine requestPasswordReset/resetPassword methods and trusted APP_BASE_URL callback. Provider reset query tokens (an upstream contract) are read client-side and scrubbed immediately; staging must audit provider/access-log retention. No new password/reset authority. Logout redirects only after provider-confirmed success; failures remain recoverable and visible.

Legacy signup/login action exports are compatibility delegates, not another auth implementation. Signup no longer writes legacy public profiles or mints another Member ID. The shared trusted provisioning entry points fail closed for unmapped historical public profiles. Historical identity migration/crosswalk requires operator review; no identity is replaced. Existing USS mappings retain DB-generated permanent identity and BE-02 provisioning rules.
